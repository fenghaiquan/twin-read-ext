# Sprint 4.1 人工验收清单

> 交付物：整页翻译体验优化——块级锚点注入、译文换行展示、翻译中标示、同页缓存、视口懒翻译。
> 实现 ADR-004 定义的四项优化，提升翻译质量和用户体验，同时控制 token 消耗。

## 手动验收步骤（Proof）

### 1. 重新加载扩展

`chrome://extensions` → Twin Read 卡片点 ↻

### 2. 核心优化 1：译文换行展示

打开英文文章页（如 Wikipedia）：

- 点击 popup「开启整页翻译」
- **预期**：译文以**独立块**显示在原文段落下方（灰色斜体 0.95em），**不再紧跟原文末尾**
- 译文与原文视觉分离，阅读体验改善

### 3. 核心优化 2：翻译中标示

滚动到未翻译区域：

- **预期**：即将翻译的段落显示灰色斜体「… 翻译中」（opacity 0.6）
- 翻译完成后，标示消失，显示实际译文
- 失败段落显示红色「⚠ 翻译失败」（可重试）

### 4. 核心优化 3：同页缓存

- 开启翻译 → 等待部分段落完成 → 关闭翻译 → 再次开启
- **预期**：已翻译段落**即时恢复**（无「翻译中」闪烁，无 API 请求）
- Network 面板：第二次开启时无新的翻译请求

### 5. 核心优化 4：视口懒翻译（token 控制）

- 开启翻译后**不滚动**
- Network 面板：初始仅发送**视口内 + 预加载 600px 范围**的批次请求
- **滚动页面** → 新段落进入视口 → 触发新的翻译请求
- **预期**：长页面只翻译用户实际阅读的部分，token 消耗可控

### 6. 块级锚点验证

- 验证翻译单位是**叶子块级元素**（p / li / h1-h6 等）
- 嵌套列表只翻叶子 li，不重复
- `<p>文字 <code>code</code> 尾部</p>` 只翻文字部分（code 跳过）
- 空白块、hidden 块、已注入块跳过

### 7. 划词功能回归（Sprint 2 不受影响）

- 在已整页翻译的页面上划词 → 圆点 → 卡片翻译功能正常

### 8. 稳健性边界

- 快速 开→关→开 → 无重复注入（runToken 丢弃迟到响应）
- 长页面（>60 段）：Network 面板中同时进行的 LLM 请求 **≤ 3**（后台限流）
- 失败批次对应 span 标「⚠ 翻译失败」，保留占位便于用户察觉

## 边界确认（架构不越界）

- [x] content 仅经 `chrome.runtime.sendMessage` 请求翻译，零直接网络（ADR-001，depcruise 强制）
- [x] 注入用 `parentNode.insertBefore`，永不改写容器 innerHTML（ADR-002）
- [x] 注入节点统一 `twin-read-trans` class，dom-parser 递归跳过 → 关→开无重复翻译
- [x] 缓存纯内存，页面刷新自然清空（无持久化开销）

## 迭代记录 2（验收反馈：译文格式与加载态）

| 项目 | 内容 |
| :--- | :--- |
| 译文格式对齐 | `matchOriginalTypography`：从原文复制 font-family/size/weight/line-height/letter-spacing/word-spacing/text-align/text-transform 及**排版宽度**（computed width）；不再强制斜体/缩小字号；表格单元格改为 td 内部追加（避免破坏行布局） |
| 加载态 | 「… 翻译中」文本占位改为**段落末尾的小旋转圆圈**（inline-block 0.7em，currentColor 环，keyframes 经一次性 `#twin-read-style` 样式表注入）；完成后移除圆圈再插入译文；失败时圆圈变为「⚠」红色小字 |
| 测试 | 注入器测试重写为 13 个用例（spinner/格式对齐/表格/失败态/一键清除），总计 **88/88** |

### 迭代验收步骤

1. 重新加载扩展 → 打开英文文章页 → 开启翻译
2. **预期**：段落末尾出现小旋转圆圈（无「… 翻译中」字样）；译文到达后圆圈消失，译文在原文下方换行展示
3. **格式**：标题下的译文与标题同字号/字重；正文译文与正文字体、行高、对齐一致；**排版宽度与原段落对齐**（含居中/max-width 布局）
4. 表格页面：译文出现在单元格内部，表格布局不破碎
5. 失败用例（改错 API Key）：段落末尾出现红色「⚠」
