## 手动验收步骤（需要人工执行）

1. **重新加载扩展**：`chrome://extensions` → Twin Read 卡片点 ↻（重要：background/content 已更新）

2. **基础划词用例**：打开任意英文网页（如 GitHub README、Wikipedia）
   - 双击选中一个单词（如 `bank`、`cell`、`pitch` 这类多义词）
   - **预期**：选区下方出现浅色圆角浮窗，先显示「正在结合上下文翻译…」，数秒后显示**结合上下文**的中文释义
     （例如科技文章中的 `cell` 应译作「单元格/电池/细胞」中符合语境的一个，而非罗列所有义项）

3. **上下文敏感性验证**（本 Sprint 的核心 Proof）：
   - 在财经新闻里选中 `bank` → 预期释义偏向「银行」
   - 在技术文档里选中 `bank` → 预期释义偏向「（数据）库/存储组」等语境化解释

4. **样式隔离验证**（ADR-003）：
   - 在样式复杂的网站（GitHub dark mode、Reddit）划词
   - **预期**：浮窗外观完全一致（白底/深色模式自适应、圆角、阴影），不被宿主 CSS 破坏
   - 宿主页面无被注入的杂散元素（浮窗内部节点对外 amount of `.shadowRoot === null`）

5. **关闭交互验证**：
   - 显示浮窗后点击页面空白处 → 浮窗消失
   - 再次划词 → 浮窗重新出现于新选区下方
   - 显示浮窗后按 `Esc` → 浮窗消失
   - 页面滚动 → 浮窗消失（避免定位失效）
   - 选区位于视口底部 → 浮窗自动翻转到选区上方

6. **错误路径用例**：
   - 暂时把 API Key 改错并保存，再划词
   - **预期**：浮窗内显示红色错误信息（如 HTTP 401），而非空白、卡死或无响应
   - 验完改回正确 Key

7. **边界用例**：
   - 选中超过 300 字符的大段文本 → **预期不触发**浮窗（留给整页翻译）
   - 双击 input/textarea 内的文本 → 预期不触发
   - 划词翻译期间点击链接 → 页面行为正常（content 未破坏宿主交互）

## 边界确认（架构不越界）
